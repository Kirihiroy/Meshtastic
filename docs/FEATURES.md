# Функции приложения

## Реализованные функции

### 1. BLE подключение к Meshtastic-устройству

- Сканирование по UUID сервиса Meshtastic
- Авто-согласование MTU до 512 байт
- Отдельный `HandlerThread` для GATT-операций
- Очередь операций `GattOp` с таймаутом 8 сек
- **Drain-loop** FromRadio (вытягивает все накопленные пакеты)
- Резервный poll FromNum раз в 1.5 сек
- Запрос разрешений BT_SCAN / BT_CONNECT / ACCESS_FINE_LOCATION

**Экран:** «Соединение» (`ConnectionFragment`)

### 2. Соединение — UI в стиле Meshtastic-Android

- Большая информационная карточка устройства (router-icon + имя)
- Сегмент-контрол транспортов: Bluetooth / Сеть / COM-порт *(только BT функционален)*
- Список «Сопряжённые устройства» с radio-button выбором
- State-aware кнопка действия: **Сканирование → Остановить → Подключиться → Отключиться**
- Статус-чип внизу: «Нет соединения / Сканирование… / Подключение… / Подключено»

### 3. Список узлов («Ноды»)

- Шапка с заголовком и счётчиком: `(онлайн X / показано Y / всего Z)`
- **Встроенный статус-баннер** (заменил отдельный экран «Статус»):
  - Цветной индикатор состояния (зелёный/жёлтый/красный/серый)
  - Текст состояния + время последнего RX
  - Метрики: батарея, SNR, версия прошивки
  - **Тап → ручная пересинхронизация** (`requestConfigManual` отправляет `want_config_id`)
- Поле фильтра (поиск по имени / hex-ID / hw-model / роли)
- Кнопка сортировки (toggle по last-heard)
- Карточка узла:
  - Цветной бейдж с коротким именем (HSV-цвет по hash от `nodeNum`)
  - Иконка замка (зелёный если есть PSK)
  - Длинное имя + иконка типа устройства
  - Last-seen (`X мин/ч/дн назад` или `Неизвестно`)
  - Иконка MQTT-off (если узел НЕ через MQTT-мост)
  - Метрики: PWR (с %), ChUtil, AirUtil, высота
  - Нижний ряд: HW-model · role · `!node-id` (с иконкой fingerprint)
- Обновление через `ListAdapter + DiffUtil` (минимальные перерисовки)

### 4. Чат — общий канал

- Шапка с заголовком и подзаголовком «Канал: LongFast · участников: N»
- Лента сообщений с тремя типами view:
  - Входящие (слева, тёмно-серый пузырь, **аватар с инициалами**, имя отправителя)
  - Исходящие (справа, тёмно-синий пузырь, иконка статуса доставки)
  - Разделитель даты (pill-chip «Сегодня / Вчера / 13 мая 2026»)
- **Группировка**: подряд от одного отправителя в пределах 5 минут — без аватара/имени, скруглённый пузырь (вместо «хвостика»)
- **Цвет аватара и имени** генерируется HSV-хешем `senderId` (стабильно)
- **Статус доставки** исходящих: ⏱ SENDING / ✓ SENT / ✓✓ DELIVERED / ⚠ FAILED
- **Hops chip** в углу пузыря для входящих из mesh-сети
- **FAB «↓ N новых»** при прокрутке вверх — тап скроллит к низу
- **Контекстное меню** по долгому нажатию: Скопировать (работает), Ответить, Удалить локально (заглушки)
- Скруглённое поле ввода + круглая зелёная кнопка отправки
- Иконка вложения слева *(пока заглушка)*

### 5. Личные сообщения с E2E-шифрованием

- Своя пара ключей **ECDH P-256**, генерируется при первом запуске
- Приватный ключ зашифрован **AES-256-GCM**, AES-ключ в **Android Keystore**
- Публичный ключ доступен для копирования (Настройки → Безопасность)
- Сообщения через порт `PRIVATE_APP` (256)
- Шифрование: эфемерная ECDH-пара + AES-256-GCM с тегом аутентификации (128 бит)
- Атомарная структура: [длина pubkey][X.509 pubkey][12-байт IV][шифртекст + GCM tag]
- При неверном теге — `AEADBadTagException`, сообщение отвергается

**Экран:** «E2E ЛС» (`E2eDmFragment`)

### 6. Меню Настроек — 10 разделов

Список разделов в стиле оригинального Meshtastic-Android. Каждый sub-экран сохраняет черновик локально в `SharedPreferences` (с раздельными секциями `loadWithX/saveX`).

| Раздел | Поля |
|---|---|
| **LoRa** | Регион, пресет модема, hop limit, TX мощность, TX enabled, Ignore MQTT |
| **Каналы** | 8 слотов (PRIMARY + 7 SECONDARY/DISABLED) + редактор каждого слота |
| **Безопасность** | E2E pubkey (read-only), 3 admin-ключа, `is_managed` |
| **Пользователь** | Имя, короткое имя, роль (11 вариантов), HAM-флаг |
| **Устройство** | Rebroadcast mode, NodeInfo period, Serial/Debug/LED toggles |
| **Местоположение** | GPS mode, broadcast period, Fixed/Smart toggles |
| **Питание** | Power saving + 3 таймера |
| **Сеть** | Wi-Fi (SSID/PSK) + NTP + Ethernet |
| **Дисплей** | Screen timeout, units, Flip/12h/Bold toggles |
| **Bluetooth** | Enabled, pairing mode, fixed PIN (6 цифр) |

### 7. Apply-на-устройство

- **Полностью реализовано:** имя PRIMARY-канала + PSK через `AdminMessage.set_channel` (метод `MeshConnectionRepository.applyChannelPsk`)
- **Не реализовано:** остальные 9 разделов настроек — только локальный черновик (см. направления развития)

### 8. Protobuf парсинг

Поддерживаемые типы `FromRadio`:
- `MY_INFO` — `myNodeNum` → отображается в баннере
- `NODE_INFO` — извлекаются `user.{id, longName, shortName, hwModel, role}`, `deviceMetrics.{batteryLevel, voltage, channelUtilization, airUtilTx}`, `position.{lat, lon, altitude}`, `snr`, `lastHeard`, `viaMqtt`, `hopsAway`
- `CONFIG` / `CHANNEL` — `lastSummary` в баннере
- `PACKET`:
  - `TEXT_MESSAGE_APP` → общий чат
  - `PRIVATE_APP` → E2E-расшифровка
- `METADATA` — извлекается `firmwareVersion`
- `LOG_RECORD` — выводится в summary

### 9. Тёмная тема

- Поддержка тёмной темы (`values-night/themes.xml`)
- Material 3 (`Theme.Material3.DayNight.NoActionBar`)
- Все экраны учитывают системные настройки тёмного режима

### 10. Локализация

- Все строки UI в `res/values/strings.xml` (русский)
- Структура готова для добавления других локалей через `values-en/`, `values-de/` и т.п.

## Direction roadmap (что НЕ реализовано)

Группировано по приоритету. Полное описание — в `CHANGELOG.md` под Unreleased.

### Высокий приоритет

- **Routing ACK обработка** → реальный ✓✓ DELIVERED статус доставки в чате
- **Apply-на-устройство** для всех 9 оставшихся разделов настроек (LoRa/User/Position/Power/Network/Display/Bluetooth/Device/Security через AdminMessage)
- **Автообмен E2E ключами** через служебное сообщение с маркером `E2E-KEY:`
- **Буфер `pendingOutbox`** для исходящих во время разрыва BLE + автоповтор после восстановления
- **Экспоненциальный retry** при ошибках BLE (1/2/4/8/16/30 сек)

### Средний приоритет

- **Постоянная история сообщений** — `Room` (зависимость подключена, нужны Entity/Dao/Database)
- **Карта узлов** — `MapLibre` (зависимость подключена, нужен `MapFragment`)
- **GPS-координаты** смартфона → POSITION_APP пакеты (`LocationHelper` есть, не вызывается)
- **Динамическое имя канала** в шапке чата (вместо константы LongFast)
- **Группировка для исходящих** в чате (сейчас группируются только входящие)
- **Контекстное меню**: Ответить (цитата сообщения), Удалить локально

### Низкий приоритет

- **QR-обмен ключами** E2E
- **Книга контактов** с сохранёнными E2E-ключами собеседников
- **Прикрепление координат** к сообщению чата
- **Push-уведомления** при свёрнутом приложении (WorkManager + Notification)
- **Foreground Service** для удержания BLE в фоне
- **Double Ratchet** вместо разовой ECDH для E2E
- **Транспорт «Сеть»** (TCP к device через Wi-Fi)
- **Транспорт «COM-порт»** (USB OTG)

## Архитектурные особенности

- **Single-Activity** + 5 фрагментов в `BottomNavigationView`
- **MVVM** через `MeshConnectionRepository` (singleton) + `LiveData`
- **ViewBinding** во всех фрагментах
- **DiffUtil** в списках узлов, каналов, сообщений
- **Раздельные потоки**: UI на main, BLE на `HandlerThread("MeshtasticBleGatt")`
- **Очередь GATT-операций** — обязательно для Android BLE (одна операция в моменте)
- **Single Source of Truth**: все экраны читают только `LiveData` репозитория, не хранят локального состояния

Подробнее — в `ARCHITECTURE.md`.
