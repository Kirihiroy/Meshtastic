# Руководство пользователя

## Обзор приложения

Android-клиент для устройств **Meshtastic**: BLE-подключение, mesh-сеть, обмен сообщениями (общий канал + E2E ЛС), настройка устройства.

## Структура интерфейса

5 экранов через нижнюю навигацию (порядок слева направо):

1. **Чат** — общий канал mesh-сети
2. **Ноды** — список узлов + встроенный статус-баннер
3. **Карта** *(в разработке)*
4. **Настройки** — 10 разделов конфигурации
5. **Соединение** — выбор и подключение к устройству (BLE / Сеть / COM-порт)
6. **E2E ЛС** *(отдельная вкладка с замком)* — личные сообщения

> Раздел «Статус» отсутствует — его метрики теперь в баннере вверху «Нод».

## 1. Экран «Соединение»

### Что на экране

```
[△ Соединение]

┌────────────────────────────────┐
│         🚫📡                   │
│   Устройство не выбрано        │
└────────────────────────────────┘

[* Bluetooth] [≈ Сеть] [⏨ COM-порт]

Сопряжённые устройства
┌────────────────────────────────┐
│ * Meshtastic_abe0       ○      │
│ * Meshtastic_4104       ○      │
└────────────────────────────────┘

         [🔍 Сканирование]

[Нет соединения]
```

### Как подключиться

1. **Включи Bluetooth** на телефоне и **запусти устройство Meshtastic**.
2. Открой вкладку **«Соединение»** (нижняя навигация, иконка BT).
3. Нажми кнопку **«Сканирование»** — пойдёт BLE-скан (до 8 секунд).
4. В списке «Сопряжённые устройства» появятся найденные узлы. **Тапни** нужный — radio button заполнится, большая карточка покажет имя устройства, кнопка станет **«Подключиться»**.
5. Нажми **«Подключиться»**. Чип внизу покажет «Подключение…», затем «Подключено».
6. Кнопка превратится в **«Отключиться»** — нажми, если хочешь разорвать связь.

### Если что-то не так

- **Чип «Нет соединения», кнопка не работает** → не дал разрешения BT_SCAN / BT_CONNECT / геолокации. Удали приложение и установи заново — спросит снова. Или дай через настройки Android.
- **Сканирование ничего не находит** → проверь что устройство включено и в радиусе 5 м. На некоторых телефонах нужна **включённая** служба геолокации (не путать с разрешением).
- **«Сеть» и «COM-порт»** — табы кликаются, но показывают Toast «не реализовано». Это намеренно — в текущей версии только Bluetooth.

## 2. Экран «Ноды»

### Что на экране

```
[△ Ноды]
   (онлайн 1 / показано 3 / всего 3)

┌────────────────────────────────────────┐
│ 🟢 Готово: Meshtastic_4104   RX 2 мин │ ← статус-баннер
│    Батарея 85% · SNR 8.5 · v2.5.4     │   (тап = пересинхр.)
└────────────────────────────────────────┘

[🔍 Фильтр                      ] [☰]    ← фильтр + сортировка

┌────────────────────────────────────────┐
│ [abe0] 🔒 Meshtastic abe0 📡    ☁❌    │
│        (•) 1 ч назад                   │
│ ⚡PWR 4,35V                            │
│ ▤ ChUtil 0,0%  〰 AirUtil 0,0%        │
│ 🖧 HELTEC_V3  👤 CLIENT  🆔 !acaaabe0 │
└────────────────────────────────────────┘
```

### Статус-баннер (бывшая «Панель состояния»)

| Цвет точки | Что значит |
|---|---|
| 🟢 зелёный | Подключено (CONNECTED) |
| 🟡 жёлтый | Сканирует/подключается |
| 🔴 красный | Ошибка |
| ⚪ серый | Не подключено |

В баннере: текущее состояние, время последнего RX, метрики моего устройства (батарея, SNR, версия прошивки).

**Тап по баннеру** → переотправка `want_config_id`. Используй, если устройство «зависло» и не присылает обновления — обычно одного тапа достаточно.

### Карточка ноды

- **Бейдж** (`abe0`) — короткое имя; цвет генерируется по hash от nodeNum (стабильно)
- **🔒 зелёный замок** — у канала задан PSK; **⚪ серый** — без шифрования
- **☁❌ красное облако** — нода НЕ через MQTT (т.е. слышим напрямую); если нет иконки — пришла через MQTT-мост
- **PWR/батарея** — напряжение и/или %
- **ChUtil/AirUtil** — загрузка канала и эфирное время
- **Высота** — если в позиции
- **HW model / role / !node-id** — нижний ряд

### Фильтр и сортировка

- **Поле «Фильтр»** ищет по имени, короткому имени, hex-ID, hw-model, роли
- **Кнопка справа от поля** — переключает порядок сортировки (по времени последнего приёма)

## 3. Экран «Чат»

### Что на экране

```
[△ Чат]
   Канал: LongFast · участников: 3

┌─ Сегодня ─┐

[abe0]  Meshtastic abe0           ↗ 2 hops
        ┌────────────────────────────┐
        │ Привет!                    │
        │                      14:32 │
        └────────────────────────────┘
        ┌────────────────────────────┐
        │ Сообщение в той же группе. │ ← без аватара
        │                      14:33 │   (5-мин окно)
        └────────────────────────────┘

                  ┌────────────────────────────┐
                  │ Окей, выхожу.              │
                  │              14:30 ✓       │
                  └────────────────────────────┘
                                        [↓ 1 новых] ← FAB

[📎  Введите сообщение...]              (➤)
```

### Что отличается от обычного мессенджера

- **Группировка** — два сообщения от одного автора в пределах 5 минут показываются без повторного аватара
- **Аватар** — цветной круг с коротким именем (4 символа). Цвет стабильно генерируется по ID отправителя.
- **Hops chip** — у входящих из mesh: «N hops» в углу. Сколько ретрансляций прошло сообщение.
- **Статус доставки** у исходящих:
  - ⏱ SENDING — отправляется
  - ✓ SENT — записано в радио
  - ✓✓ DELIVERED — получен ACK от адресата *(пока всегда показывается ✓ — обработка ACK в направлениях развития)*
  - ⚠ FAILED — ошибка или таймаут
- **FAB «↓ N новых»** — появляется когда ты прокрутил вверх и пришло новое сообщение. Тап → к низу.
- **Долгое нажатие на сообщение** → меню «Скопировать» (работает), «Ответить»/«Удалить локально» (Toast «не реализовано»)

### Отправка

1. Подключись к устройству (вкладка «Соединение»).
2. Открой «Чат». Если не подключён — поле ввода серое, баннер «Нет подключения».
3. Набери текст (до ~228 байт UTF-8) → ➤.
4. Пузырь сразу появляется справа с ✓.

## 4. Экран «E2E ЛС» (личные сообщения)

### Как это работает

- При **первом запуске** приложение сгенерировало тебе пару ключей **ECDH P-256**. Приватный лежит в защищённом Android Keystore, ты его не видишь. Публичный — длинная hex-строка ~178 символов.
- Личное сообщение шифруется **AES-256-GCM** через общий секрет от ECDH. Расшифровать может **только владелец конкретного приватного ключа**, чей публичный ты использовал.
- Идёт через ту же радиосеть, но в порту **PRIVATE_APP** (256) — в общем чате не видно.

### Что нужно чтобы написать кому-то

От собеседника нужны **два значения**:

1. **Node-ID**: `!aabbccdd` (8 hex) — видно в карточке его узла на «Нодах», правый нижний угол с иконкой отпечатка пальца.
2. **Публичный ключ** (hex): он копирует из своих **Настройки → Безопасность → Копировать**, шлёт тебе любым способом (общий чат, мессенджер, бумажка).

### Шаги

1. Открой вкладку **«E2E ЛС»** (иконка замка в нижней нав).
2. В поле **«Узел получателя»** → введи `!aabbccdd` (или число).
3. В поле **«Публичный ключ получателя»** → вставь длинную hex-строку.
4. Набери сообщение → **«Отправить E2E»**.

После одного раза эти поля сохраняются на экране — переписка идёт без повторного ввода.

### Чтобы ОН ответил тебе

По симметрии — он должен знать **твой** node-ID (увидит в Нодах) и **твой** публичный ключ (ты его копируешь из **Настройки → Безопасность → Копировать**).

### Если получатель видит «[Не удалось расшифровать]»

- Он использует ключ от другого приложения (другое устройство / переустановка)
- Или ты ошибся при копировании hex-ключа

### Что в разработке

- Автообмен ключами через служебное сообщение с маркером `E2E-KEY:` — чтобы не копировать вручную
- QR-код для ключа
- Локальная книга контактов с сохранёнными ключами

## 5. Экран «Настройки»

### Структура меню

```
[△ Настройки]

┌──────────────────────────────┐
│ ((•)) LoRa             ❯    │
│  ☰    Каналы           ❯    │
│  🛡   Безопасность      ❯    │
└──────────────────────────────┘

Настройки устройства

┌──────────────────────────────┐
│  👤  Пользователь       ❯    │
│  🖧   Устройство         ❯    │
│  📍  Местоположение     ❯    │
│  🔌  Питание            ❯    │
│  📶  Сеть               ❯    │
│  🖥   Дисплей            ❯    │
│  ⌬   Bluetooth           ❯    │
└──────────────────────────────┘
```

10 разделов, каждый открывает свой sub-экран с формой и кнопкой «Сохранить как черновик».

### Что в каждом разделе

| Раздел | Поля |
|---|---|
| **LoRa** | Регион (19 кодов), пресет модема (8 вариантов), hop limit (1–7), TX мощность (0–30 dBm), TX включён, Игнорировать MQTT |
| **Каналы** | Список 8 слотов (PRIMARY + 7 SECONDARY/DISABLED). Тап → редактор: имя (до 11 символов), PSK (hex 32 или 64), роль |
| **Безопасность** | Мой E2E pubkey (read-only + копировать), 3 доверенных admin-ключа, переключатель `is_managed` |
| **Пользователь** | Длинное имя, короткое имя (4 символа), роль (11 вариантов), HAM-оператор |
| **Устройство** | Режим ретрансляции, период NodeInfo, Serial console, Debug log, LED heartbeat |
| **Местоположение** | Режим GPS, период отправки позиции, Fixed Position, Smart Position |
| **Питание** | Энергосбережение, shutdown after, wait Bluetooth, min wake (секунды) |
| **Сеть** | Wi-Fi enabled + SSID + PSK, NTP сервер, Ethernet enabled |
| **Дисплей** | Период автогашения, единицы (METRIC/IMPERIAL), Flip / 12h time / Heading bold |
| **Bluetooth** | Enabled, режим pairing (RANDOM_PIN/FIXED_PIN/NO_PIN), фиксированный PIN (6 цифр) |

### Важно

⚠️ В текущей версии все значения сохраняются **только локально** как черновик (в `SharedPreferences`). Применение на устройство через `AdminMessage` работает **только для имени канала и PSK** primary-канала. Push остальных Config/ModuleConfig — направление развития.

### Навигация

- Стрелка ← возвращает на меню Настройки
- Системная кнопка «Назад» тоже работает
- Переход на другую вкладку bottom-nav → возврат на корневое меню (back stack чистится)

## 6. Сценарии использования

### 6.1 Быстрая проверка связи

```
Соединение → Сканирование → выбрать устройство → Подключиться
Ноды       → проверить что появляются ноды
Чат        → отправить тест-сообщение
```
~2 минуты.

### 6.2 Настройка приватного канала для группы

```
Настройки → Каналы → тап на слот 0 (PRIMARY)
  → ввести имя канала и PSK (hex 32 или 64) → Сохранить как черновик
Передать имя/PSK команде вне приложения (бумажка/QR)
```
*Apply-на-устройство для PRIMARY канала пока единственное что реально летит на железо.*

### 6.3 Личная переписка

```
1. Я открываю Настройки → Безопасность → Копировать pubkey → отправляю собеседнику
2. Собеседник делает то же самое и присылает мне свой
3. На Нодах я смотрю его !aabbccdd
4. E2E ЛС → вставляю его ID и его pubkey → пишу
```

## 7. Диагностика

### Логи через ADB

```powershell
# Все логи приложения
adb logcat | Select-String "Meshtastic"

# Только BLE
adb logcat | Select-String "BleManager"

# Только repository
adb logcat | Select-String "MeshConnectionRepo"
```

### Тапни статус-баннер в Нодах

Если ноды не появляются после подключения — **тап по баннеру** переотправит `want_config_id`. Это вызывает повторный стрим NodeInfo от устройства.

### Жизненный цикл подключения

1. `Соединение` → нажал «Сканирование» → state = SCANNING
2. Выбрал устройство → state = SCANNING (просто запоминается)
3. Нажал «Подключиться» → state = CONNECTING (чип «Подключение…»)
4. Прошивка отдала CCCD-подтверждение → state = CONNECTED + автоматический want_config_id
5. Устройство шлёт MyInfo / NodeInfo* / Config* / ConfigComplete — Ноды заполняются

## 8. Что НЕ работает (направления развития)

- **Apply-на-устройство** для большинства настроек (кроме PRIMARY канала)
- **Routing ACK** → ✓✓ статус доставки сообщений
- **Автообмен E2E ключами** + QR-коды
- **Реконнект** при разрыве BLE
- **Буфер исходящих** на время разрыва
- **GPS-координаты** в POSITION_APP
- **Карта** узлов (зависимость MapLibre подключена)
- **Постоянное хранение** истории сообщений (зависимость Room подключена)
- **Push-уведомления** при свёрнутом приложении

Полный список и приоритеты — в `FEATURES.md` и `CHANGELOG.md`.
